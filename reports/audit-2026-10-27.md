## Findings, most severe first

### 1. HIGH (for clanmates; Birj is not exposed): tidy does not guard Philter's settings that send, buy or blanket-sell

- **Where:** `tidy_common.ash:881-902` (`common_guards` only forces `BaleOCD_EmptyCloset`, and the run
  sets `BaleOCD_Sim` and `BaleOCD_DataFile`). The Philter side is `philter.js:231-232` (defaults:
  `BaleOCD_MallMulti` empty, `BaleOCD_UseMallMulti` **true**), `:1077-1079` (`shouldUseMulti`),
  `:1096-1098` and `:1136-1160` (`sendToMallMulti` kmails the items), `:1783-1792` and `:1855-1858`
  (`BaleOCD_Stock=1` makes Philter buy through `retrieveItem`), and `:1357-1358` (`BaleOCD_MallDangerously`
  malls any item that has no rule).
- **Failure scenario:** a clanmate set up Philter years ago with a mall multi (`zlib BaleOCD_MallMulti =
  myMallAlt`), which was a common setup in the OCD era. They install tidy and run `tidy go`. Every
  MALL item, including every rule tidy released from hold, is **kmailed to the alt** instead of being
  listed. README.md:296-297 promises "No kmail, no trades... no buying". The same applies to
  `BaleOCD_Stock = 1` with an `OCDstock_<name>.txt` (Philter spends meat buying stock) and to
  `BaleOCD_MallDangerously = true` (any kind created mid-run by a MAKE or USE rule is malled without
  asking).
- **Birj's exposure:** none today. `Kolm/data/vars_Birj.txt` lists only `BaleOCD_EmptyCloset -1`, and the
  vars file leaves out values equal to the defaults, so MallMulti is empty, Stock is 0 and
  MallDangerously is false.
- **Fix:** in `common_guards`, read `vars` (the map, as the EmptyCloset check already does) and refuse
  the run, naming the one-line fix, when `BaleOCD_MallMulti` is non-empty while `BaleOCD_UseMallMulti`
  is true, when `BaleOCD_Stock` is 1, or when `BaleOCD_MallDangerously` is true. Refusing is better than
  overriding: these are the user's own choices, so tidy should say so and stop, the same way it does
  for CLAN, GIFT and DISC. README "Guards" and "What it never does" get the matching lines.

### 2. MEDIUM (non-default setting): with `tidy_holdNewDays = 0`, a brand-new rule skips the worn-gear floor

- **Where:** `tidy_common.ash:1385-1396`. A new rule is written with `rule.q = verdict.q`, and
  `keep_floor()` is applied only through `hold_new_rule` (holds on) or on the next run's keep-count check
  (`:588-608`, which already ran earlier in this run, before the new rules existed). The two `decide()`
  branches that can come in under the floor are the keep-list branch (`:638-642`, keep = the listed
  count) and the lazyman rule (`:651-652`, AUTO keep 0, gear included).
- **Failure scenario:** holds are off (`set tidy_holdNewDays = 0`) and the keep list says
  `seal-clubbing club 1`. Birj wears one club, has one in the bag and one in the closet, and the club has
  no rule yet. `decide` returns MALL keep 1. Philter then sees 3 on hand with keep 1, an excess of 2. Its
  `cleanupAmount` calls `retrieveItem(2)` with 1 in the bag (`philter.js:1205-1207`), which takes the
  worn club off, and both clubs are malled at market. The lazyman rule does the same to any worn gear
  that is new to the rule file. With the default hold of 1 day this is safe, because the release uses
  `max(decided, keep_floor)` (`:1329`).
- **Fix:** where the new rule is built (`:1385`), and the same in `bootstrap_rules` (`:694`) and
  `closet_bootstrap` (`:964`), for MALL and AUTO set `rule.q = max(verdict.q, keep_floor(it, pieces))`.
  That covers every rule-writing path, not just this one.

### 3. LOW: Philter counts Hagnk's storage, tidy does not

- **Where:** `philter.js:711-723` (`fullAmount` adds `storageAmount` whenever `autoSatisfyWithStorage`
  is false, and Philter forces it false at `:1919-1923`). Compare `tidy_common.ash:480` (`on_hand` = bag
  + closet + worn).
- **Failure scenario:** a held MALL rule holds `on_hand` = 5, and 2 more copies sit in Hagnk's. Philter
  counts 7 against keep 5, an excess of 2, and sells 2 bag copies of a rule that is still on hold. The
  guard at `:894-895` (Hagnk's emptied this ascension) makes this rare in aftercore, but it does not
  rule it out. Items can reach storage after `pull all`, and `pull all` leaves behind what cannot be
  pulled. The same off-by-storage applies to the top-up count and to the worn-gear floor.
- **Fix:** add `storage_amount(it)` to `on_hand()`, the one formula everything already shares (the
  campground stays a documented limit). Add it to DESIGN.md "Known limits" either way: at present
  that list names only the campground.

### 4. LOW: a preview after the day's live reprice reports reprices the live run will not make

- **Where:** `tidy_common.ash:727` (the "already repriced today" skip is live-only: `!sim && ...`).
- **Seen for real:** on 10-26 the evening preview said "would reprice 40 listings to market" (log line
  111184). The live run straight after said "store already repriced today; skipping that step" (line
  111598). The later preview repeated the 40 (line 112538). So the preview and the live run disagree,
  and the preview is what Birj reads.
- **Fix:** in a preview, when `repriceDay == RUN_DAY`, print "already repriced today; a live run skips
  this step" and return. Keep the full "would reprice" listing for the first preview of the day.

### 5. LOW: the preview's top-up line shows the pre-reprice price

- **Where:** `tidy_common.ash:1436` and `:1450`. A preview reprices nothing, so `shop_price()` is
  still the old price when the top-up line prints it.
- **Failure scenario:** a listing at 10,000 that the reprice would cut to 7,000 shows in the preview as
  "would add 3 ... at your price of 10,000". The live run adds them at 7,000. The live behaviour is
  correct: on the 10-26 morning live run, all 31 items that were both repriced and topped up went in at
  the repriced price, with no mismatches. Only the preview text is wrong.
- **Fix:** have the preview's reprice remember its would-be prices in a map and use them in the top-up
  line, or add "(before today's reprice)" to the preview's wording.

### 6. LOW: the closet run lowers a CLST count only when it sits exactly on the floor

- **Where:** `tidy_common.ash:933` (`rules[it].q == keep_floor(it, pieces)`).
- **Failure scenario:** a CLST rule on an outfit piece was hand-set to 3, above its floor of 2. On
  `tidycloset go` it is not lowered, so after the closet is emptied 3 copies stay in the bag, unworn.
  This is the same outcome PR 24 and PR 25 fixed for the at-floor case. PR 24's change at `:595-596`
  never raises a count, so it does not cause this. It just cannot lower one.
- **Fix:** test `rules[it].q >= keep_floor(it, pieces)` and leave the rest unchanged. Or decide that a
  count above the floor is a hand choice, and say so in README.md:49. Either way it is Birj's call.

## Checked and found sound

- **Top-up arithmetic** (`:1433-1455`). The excess is `on_hand - max(q, keep_floor)`, capped at the bag
  count. That is exactly what Philter would sell (`philter.js:1220`), so Philter finds nothing left to
  move. The price is Birj's listing price after the reprice (confirmed on 31 of 31 items on 10-26), and
  his per-buyer limit is kept.
- **Reprice.** It never raises in `down` mode (`:762`, `:775`). The cut is capped at `tidy_maxCutPct`
  (`:771-774`). It never goes below KoL's floor (`:245`, `:263-264`, `:773`) or the rule's minimum
  (`:766-767`, applied before the cap, and the cap only raises). Listings at 999,999,999 or more and
  pinned listings are skipped. The day is recorded before the first change (`:739`). Integer overflow is
  not possible here: ASH `int` is 64-bit, and the largest product is `cur * cutPct` at about 1e11.
- **Holds.** Bag, closet and worn copies are counted. Copies picked up meanwhile are raised into the
  hold (`:1355-1357`). Only a live run releases a hold, after a fresh search (`:1334-1351`), and the
  release keeps the floor (`:1329`). A hand edit drops the hold, but tidy's own raise does not
  (`:1321-1326`).
- **Drip.** MALL only, skips held rules, and the keep-count is set to on hand, at or above the floor
  (`:857-859`).
- **Closet copies.** They are never pulled out except by `tidycloset go`. tidy forces
  `BaleOCD_EmptyCloset` to -1 (`:897-901`), and Philter turns closet auto-satisfy off while it runs
  (`philter.js:1919-1923`).
- **PR 24 and PR 25.** The closet-run CLST count is set to the worn copies or the keep-list count with
  no minimum (`:942-943`), and the keep-count check leaves it there during the run (`:595-596`). The two
  agree, and the next day's floor restores the count once the copies are closeted.
- **Rule-file safety.** The parse check comes before `.prev` (`:1238`, `:501-511`), and item keys go
  through `[id]name`, so renamed items keep their rule. ASH name lookups are case-insensitive, and
  `exact_item` handles that by comparing in lower case and in both entity forms (`:209-210`).
- **Philter stopping early.** The data-file pointer and the sim switch are put back (`:1473-1475`), the
  preview is not recorded as a look (`:1478`), and the reset backup is not cleared (`:1480`). The run
  that stopped is not undone. That is documented in DESIGN.md "Known limits".
